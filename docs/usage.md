# 登録・設置・運用ガイド

## 1. まず動作を試す

READMEの手順でnvmを初期化して`nvm use`し、以下を実行する。

```bash
npm ci --ignore-scripts
npm run demo
```

`http://localhost:4173/siw-ad/`を開く。アプリを選ぶと、自分以外のサンプルが画面下の設置イメージに表示される。「再抽選」で読み込み直し、「コピー」で埋め込みコードを取得できる。画面下への固定を外すと、通常配置のiframeコードになる。

サンプルのリンク先は`example.com`であり、実際の作品ではない。`examples/`に隔離しているため、通常のビルド・本番配信には混ざらない。サンプル画像を再生成する場合だけ、`node examples/generate-images.mjs`を実行する。

サーバーはCtrl+Cで停止する。本番データを試す場合は`npm run build`後に`npm start`。ポートを変える場合は`PORT=4174 npm start`のように指定する。ローカル配信もPagesと同じ`/siw-ad/`配下を使う。

## 2. アプリを登録する

登録対象は学校のコミュニティで作った作品。登録する文章・画像・リンク先は、一般公開してよい内容にする。画像の掲載権利を確認し、認証情報・学籍番号・個人のメールアドレスなどは入れない。

1. `images/`に画像を追加する。PNG・JPEG・WebP、500 KiB以下。ファイル名は英数字・ハイフンなどを使い、拡張子は小文字にする。推奨比率は16:9だが、バナーでは正方形にトリミングされるので中央に主な要素を置く。
2. `ads/<id>.json`を追加する。
3. `npm run check`を実行する。
4. PRに対象作品と変更内容を書き、管理者にレビューを依頼する。

`ads/my-app.json`の記入例（URL・画像は自分の作品に置き換える）:

```json
{
  "id": "my-app",
  "name": "アプリの名前",
  "description": "誰に何ができるアプリなのかを短く紹介します。",
  "url": "https://example.com/",
  "image": "images/my-app.png",
  "enabled": true
}
```

IDは小文字英数字と単語間のハイフンで2〜64文字。ファイル名と一致させる。名前は60文字以下、紹介文は140文字以下。前後に空白を付けない。バナー内はそれぞれ1行なので、特に名前と紹介文の先頭に要点を置く。省略されてもリンクのアクセシブルな名前には全文が含まれる。

URLは公開用の絶対HTTPS URLとする。認証情報・localhost・IPアドレスは使用できない。自動検証はURLの形式を確認するもので、リンク先の公開状態や内容までは保証しない。

管理者は申請者と作品の関係、リンク先、画像の権利、重複登録を確認する。掲載停止中のレコードも検証対象になる。

## 3. 自分のアプリに設置する

掲載反映後、公開サイトを開き、「設置するアプリ」で自分のIDを選ぶ。コードをコピーしてアプリに埋め込む。

- 標準は幅100%・最大720px・高さ72pxの横長バナー。
- 表示対象の最小幅は280px。広告内は画像・名前・短い紹介文を横に並べる。
- 自分のIDを指定すると、その作品は抽選から外れる。
- リンクは利用者の操作で新しいタブに開く。
- コードにトークンを入れたり、閲覧者がGitHubへログインしたりする必要はない。

### 画面下に固定する場合

「画面下に固定する」を有効にしたコードを`body`の末尾へ設置する。コードには固定枠と、本文末尾がバナーに隠れないための余白が含まれる。ホームバーの領域は`env(safe-area-inset-bottom)`で確保する。端末でこの領域を使用する場合、設置元のviewport設定にも`viewport-fit=cover`を追加して実機で確認する。

設置元に固定フッター・ボトムナビ・チャットボタンがある場合、コードを貼るだけでは配置を判断できない。アプリ側でバナーとナビの位置、本文の余白、z-indexを調整する。本文が独立したスクロール領域なら、その領域に余白を確保する。既存の画面構成に合わせたい場合は固定を外し、アプリ側のフッター領域にiframeだけを置く。

### 通常配置の場合

「画面下に固定する」を外すと、iframeだけを取得できる。

```html
<iframe
  src="https://siw-gw.github.io/siw-ad/embed/?app=my-app"
  title="コミュニティのアプリ紹介"
  width="320" height="72"
  loading="lazy" referrerpolicy="no-referrer"
  style="display:block;width:100%;max-width:720px;margin-inline:auto;border:0;"
></iframe>
```

この公開URLは標準Pages構成の想定。実際には公開後に案内ページから生成したコードを使う。ローカルでコピーしたコードはlocalhostを指すため、そのまま本番アプリに貼らない。

CSPを使うアプリは、`frame-src`に実際の配信元（標準構成では`https://siw-gw.github.io`）を許可する。`frame-src`を省略して`default-src`を使っている場合も調整が必要。iframe内のJavaScriptを無効にするsandbox設定は、配信やリンクを妨げるため動作を別途確認する。

## 4. 更新・停止・再開

- 更新: 同じIDのJSON・画像を編集してPRを作成する。IDは原則変更しない。
- 停止: `enabled: false`にする。JSONは削除せずIDを残す。
- 再開: `enabled: true`に戻す。

停止したアプリでも、設置済みの広告枠で他作品を紹介できる。別作品の掲載条件として広告枠の設置を強制する仕組みはない。

反映完了はマージ時点ではなく、配信の成功後。停止時は公開`ads.json`の`ads`から対象IDが除かれたことと、新しい読み込みで表示されないことを確認する。`registeredAppIds`にIDが残るのは正常。

開いたままの広告は自動更新されない。キャッシュや配信反映にも時間がかかるため、即時停止は保証しない。公開履歴や他者の保存済みデータは、`enabled: false`では消えない。

## 5. 管理者の初回公開手順

以下は設定・公開作業の手順であり、この文書の作成によって実行されたものではない。

1. コードと広告データをレビューし、`npm run check`が成功することを確認する。
2. リポジトリのSettings → Pages → Build and deploymentで、SourceをGitHub Actionsにする。
3. Organization / EnterpriseのActionsポリシーでワークフロー中の公式Actionsが使えることを確認する。
4. `main`へコードを反映する。すでに反映済みの場合は、Actionsの「Validate and deploy」を`main`から手動実行する。
5. `Validate, test and build`と`Deploy to GitHub Pages`の成功を確認する。
6. デプロイ結果のURLを開き、ログアウト状態の別ブラウザから広告枠を確認する。
7. 実際のアプリからの埋め込み、リンク、スマートフォンの本文・ナビ・ホームバーとの重なりを確認する。

PRでは検証・テスト・ビルドだけを行い、公開しない。配信は`main`のみ。デプロイ用権限は配信ジョブに限定する。Pages用の長期トークンを手動で作る必要はない。

ブランチ保護は別途設定し、PRレビューと`Validate, test and build`をマージ条件にすることを推奨する。誰をレビュー担当にするかはコミュニティ側で決める。

## 6. 配信に失敗した場合

Actionsの失敗したジョブとログを確認する。検証に失敗したら、指摘されたJSON・画像を修正する。Pagesの配信に失敗したら、PagesのSource、Actionsの許可、`github-pages`環境の保護条件を確認する。

失敗中は旧版が公開され続ける場合がある。修正後、最新の`main`を対象にワークフローを再実行する。古いデプロイを再公開しない。復旧後に公開データとカードを確認する。

## 7. データ収集と制約

独自の表示・クリック計測、Cookie、ローカルストレージは使わない。広告枠・画像の取得では配信元への通信があり、クリック後は紹介先への通信になる。ホスティング側のアクセス処理は存在する。

抽選は読み込み時に1回だけ。複数回続けて同じ広告が出ることがあり、表示回数の均等化は行わない。`app`は自己申告のIDであり、設置元を認証するものではない。

GitHub Pagesは無償の学校内作品紹介を前提に使用する。商用サービスへの拡張時は、[Pagesの利用制限](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)に照らして配信先を再検討する。
