# SIW AD 初期構想案

更新日: 2026-11-11

この文書は初期版の目的・範囲・運用方針をまとめる。[詳細設計](./design.md)と[利用手順](./usage.md)を参照する。ローカル実装を進めており、Pagesの公開設定は別作業とする。

## 1. 目的

学校のコミュニティで作ったアプリを、他のメンバーのアプリ内で紹介し合えるようにする。作者が広告データを登録し、各アプリに共通の広告枠を設置すると、登録された他のアプリがランダムで表示される。

初期版では、卒業制作などの作品を知ってもらい、使ってもらうことを目的とする。広告料金・収益分配・商用の広告取引は扱わない。

## 2. 合意した方針

| 項目 | 方針 |
| --- | --- |
| リポジトリ | Organization `SIW-GW` の `siw-ad` を使う |
| 公開範囲 | ソース・広告データ・画像をpublicで管理する |
| データ保存 | リポジトリ内のJSONと画像。DBは設けない |
| 登録・更新 | PRを作成し、レビュー後にマージする |
| 配信 | GitHub Pagesに静的な広告表示ページを公開する |
| 閲覧 | Organizationへのログイン不要。ブラウザにGitHubのトークンを渡さない |
| 表示 | 有効な広告から設置元のアプリを除き、ランダムで1件選ぶ |
| 自動検証 | 必須項目・ID重複・URL形式・画像の存在などを確認する |
| 掲載停止 | `enabled: false` を配信更新後に反映する |

2026-11-11のGitHub確認では、リポジトリはPUBLIC、確認したアカウントの権限はADMIN、Organizationは公開Pagesの作成を許可していた。Pages取得APIは404を返しており、サイトは未設定とみられる。これは確認時点の状態であり、公開済みを意味しない。

## 3. 利用者と役割

| 役割 | 行うこと |
| --- | --- |
| アプリの作者 | 広告データ・画像の登録、更新、停止のPRを作る |
| 広告枠を設置する人 | 自分のアプリに埋め込みコードを設置する |
| コミュニティの管理者 | 掲載内容のレビュー、マージ、配信失敗時の対応を行う |
| アプリの利用者 | 紹介カードを見て、紹介されたアプリへ移動する |

作者と広告枠の設置者は同じ人でもよい。初期版では、広告枠を設置しているかどうかを掲載条件にせず、相互掲載の実績や回数も検査しない。

## 4. 利用の流れ

1. 作者が、アプリごとのJSONと紹介画像を追加するPRを作る。
2. CIがデータとビルドを検証する。
3. 管理者が、申請者・掲載内容・リンク先を確認してマージする。
4. GitHub Actionsが広告データと表示ページをビルドし、Pagesに配信する。
5. 作者が、自分のアプリIDを指定した埋め込みコードをアプリに設置する。
6. 利用者がそのアプリを開くと、広告枠に他の作品が1件表示される。

URLを通常のリンクとして貼るだけではカードは表示されない。初期版は、Webアプリに`iframe`のコードを埋め込む方法を提供する。

## 5. 初期版の範囲

### 作るもの

- アプリごとの広告データ形式と、記入例。
- PRによる登録・更新・停止の手順。
- データ検証と静的サイトのビルド。
- ランダムで紹介を表示する高さ72pxの横長バナーと、画面下への設置コード。
- 埋め込みコード、サイズ、設置先の設定を説明する利用ガイド。
- PR時の検証と、マージ後のPages配信ワークフロー。

### 初期版では扱わないもの

- DB、独自のログイン機能、ブラウザからの登録・編集画面。
- 表示回数・クリック数の収集、個人に合わせた配信。
- 課金、クリック報酬、収益分配、ランキング。
- ネイティブアプリ専用SDKや、任意のHTMLを使う広告。
- 表示回数の均等化、不正な埋め込みの防止、掲載実績の強制。

## 6. 完成条件

- 2つ以上のアプリをPR経由で登録できる。
- アプリAの広告枠でアプリBが表示され、アプリA自身は表示されない。
- 複数候補がある場合に、読み込みごとの抽選で候補を選べる。
- カードから登録したURLへ移動できる。
- 不正なデータのPRをCIで検出できる。
- 掲載停止が配信更新後の新しい読み込みに反映される。
- 候補がない場合や読み込み失敗時にも、広告枠の表示が崩れない。
- GitHubにログインしていないブラウザでも埋め込みが表示される。

## 7. 前提と今後の判断

公開データはコミュニティ外からも閲覧・再利用され得る。掲載停止は新しい広告配信を止める操作であり、Git履歴や外部に保存されたデータの削除ではない。

Pagesの利用は無償の作品紹介を前提にする。商用の広告サービスへ用途を広げる場合は、[GitHub Pagesの利用制限](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)に照らして配信先を再検討する。

実装はHTML/CSS/JavaScriptとNode.js 24.22.1の標準機能を使い、本番依存パッケージは追加しない。画面下でアプリの表示を占領しない横長バナーにする。Pagesの有効化、ブランチ保護、公開作業は文書作成・ローカル実装とは別途扱う。
